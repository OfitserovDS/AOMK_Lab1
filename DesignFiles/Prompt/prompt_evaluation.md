# Проверка и улучшение системного промта (05.10.2026)

Промт `system_prompt_acom_c89.md` версии 1.0 был составлен после разработки компонента:
каждое правило выведено из реальной ошибки, найденной при разработке (табл. 6.3 отчета).
Чтобы проверить, работает ли он на самом деле, компонент несколько раз генерировался заново
«чистыми» агентами по одному и тому же заданию, а результат проверялся скрытым тестом.
Ниже - методика, результаты и изменения промта по версиям 1.0 -> 1.1 -> 1.2.

## Методика

- **Генератор.** Отдельный агент Claude Sonnet 5.5 (Claude Code), новый для каждого прогона,
  без доступа к проекту и к переписке разработки. Системный промт передается в начале
  задания в блоке `<system_prompt>`.
- **Вход - одинаковый во всех прогонах**: тема задачи 37 дословно,
  общие требования лабораторной работы, уточнения поведения по контракту; каркас проекта из
  Eco Wizard с CID проекта и зафиксированным публичным контрактом `SharedFiles`
  (интерфейсы, IID/CID, коды ошибок); материалы курса (стилистические соглашения,
  инструкция по среде).
- **Запрещено агенту:** эталонный проект, его резервная копия, память ассистента, промты
  курса Eco.AI.Promts. Соблюдение проверено скриптом-аудитом журналов агентов:
  обращений к запрещенным путям нет ни в одном прогоне.
- **Контроль:** прогон r0 - то же задание без системного промта.
- **Приемка (один и тот же скрипт для всех прогонов):**
  - сборка файлами агента: статическая и динамическая библиотеки, предупреждения;
  - скрытый приемочный тест - юнит-тест эталонного проекта (на момент эксперимента -
    132 проверки), агентам не показывался; в статическом и динамическом режиме (свой каталог среды выполнения);
  - отсутствие libc: `nm -u` статической библиотеки, `readelf` NEEDED у .so, компиляция
    для Eco OS (arm-none-eabi-gcc, -ffreestanding) и `nm -u` (допустимы только `__aeabi_*`);
  - контрольная компиляция `gcc -std=c89 -pedantic -Wall -Wextra -Wcast-qual` (предупреждения
    только в коде компонента);
  - регистрация новых исходников во всех файлах сборки (4 Makefile, .vcxproj, .filters);
  - оформление по стандарту курса (`Eco.AI.Promts/Stack/ru/c.md`) и шаблонам мастера:
    UTF-8 с BOM, CRLF, шапки файлов, блоки `<summary>` у функций;
  - глобальные символы статической библиотеки без суффикса пространства имен `_4CAA1B2F`.
- **Проверка самой приемки:** на эталонном проекте - все критерии выполнены (одно
  предупреждение строгой компиляции - допустимое, см. п. 5.1 промта v1.2).

## История версий

### v1.0 - исходная
Составлена по итогам разработки (10 правил против 10 реальных ошибок, табл. 6.3 отчета).
**Результат r1 в сравнении с контролем r0:** функционально оба прогона безупречны.
Современная модель и без промта решает задачу, сама находит `-fno-stack-protector` и порядок
библиотек. Промт дал то, чего не видит функциональный тест:
- оформление по стандарту курса: BOM/CRLF 0/3 -> 3/3, описания функций 19/31 -> все;
- уникальные глобальные символы: 4 -> 0.

**Найденные пробелы** (одинаковы у r0 и r1):
1. 8 предупреждений строгой компиляции, все в коде каркаса мастера:
   - `(UGUID*)&CID_...` снимает const;
   - неиспользуемые параметры `Init`/`create`.

   Правило 2.4 агент применил только к своему коду: код мастера считал чужим.
2. Динамический тест (`MakefileExe`, `TARGET=0`) не компонуется: шаблон подключает
   статическую Eco.System1. Пункт 5.4 v1.0 говорил только, откуда грузятся компоненты.
3. Агент не проверял динамический режим и сборку для Eco OS.

### v1.1
- п. 4.5 (новый): код мастера - часть результата; список известных дефектов шаблона.
- п. 5.1: измеримая цель «0 предупреждений» с явными исключениями (заголовки фреймворка,
  const-источник в `IEcoMemoryAllocator1::Copy`).
- п. 5.4: как исправить `MakefileExe` для динамического режима и как проверить тест в
  собственном каталоге среды выполнения, не меняя общий.
- п. 5.6 (новый): сборка и запуск теста во всех четырех конфигурациях, компиляция для Eco OS.

**Результат r2:** цели достигнуты:
- предупреждений строгой компиляции 9 -> 1 (допустимое);
- динамический тест собирается и проходит.

Регрессия, вызванная формулировкой п. 5.1: агент внес
`-pedantic -Wextra -Wcast-qual` в `Makefile`, и обычная сборка печатает 247 замечаний из
заголовков фреймворка. Флаги для Eco OS агент подбирал сам: `-std=c89` с заголовками
фреймворка не работает.

### v1.2 - итоговая
- п. 5.1: строгие флаги - только для отдельной контрольной компиляции, в `Makefile` их не
  добавлять; обычная сборка - без предупреждений.
- п. 5.6: точные флаги `arm-none-eabi-gcc` для Eco OS.

**Результат r3:** все критерии выполнены одновременно - единственный такой прогон.

## Найденный дефект юнит-теста проекта
Скрытый тест у r2 показал 131/132: «Тест 4: точность не растет от float к long double».
Float-версия r2 воспроизвела кубический многочлен на узлах-двоичных дробях без ошибки (0),
а проверка требовала строгого роста ошибки от long double к float.

Дизассемблирование `splinef`: 92 операции одинарной точности и ни одной операции double.
Восемь преобразований - это значения граничных условий из `ldouble_t`. То есть float
действительно считается во float, ошибка - в эвристике теста, а не в коде.

Проверка в `UnitTestFiles/SourceFiles/EcoAdvancedMath.c` заменена на согласованность
перегрузок между собой:
- |S_float - S_double| <= 200 eps_float;
- |S_double - S_long double| <= 200 eps_double.

Число проверок (132) и вывод теста не изменились. С исправленным тестом r2 проходит 132/132;
эталон проходит во всех четырех конфигурациях.

При аудите 10.10.2026 в тест 4 добавлены проверки кодов возврата `splinel` для граничных
условий S', S'' и естественного сплайна (раньше при ошибке вызова проверка точности могла
пройти на результатах предыдущего вызова); теперь в тесте 136 проверок. Числа 132 в этом
протоколе относятся ко времени эксперимента.

## Ограничения
- По одному прогону на версию; генерация недетерминирована, повторные прогоны могут
  отличаться.
- Генератор - модель того же семейства (Claude), что и ассистент, составивший промт.
- Сборки Windows (gcc, MSVC, VS 2022) не проверялись - нет инструментов; Eco OS проверялась
  компиляцией исходников компонента, без сборки образа ОС.
- Каркас для прогонов, журналы агентов, сгенерированные проекты и вспомогательные скрипты
  эксперимента (задание агентам, приемочная проверка, аудит журналов) хранились во временном
  каталоге сессии и в проект не входят.

## Код, сгенерированный по промту v1.2 (прогон r3)
Функция метода прогонки из `HeaderFiles/CEcoSplineTemplate.h` агента r3 полностью, без правок
(шаблон подключается для float, double и long double):

```c
/*
 *
 * <summary>
 *   solve function
 * </summary>
 *
 * <description>
 *   Построение коэффициентов кусочно-полиномиальной формы методом прогонки (алгоритм Томаса)
 *   для трехдиагональной системы относительно наклонов S'(x[i]). Входные данные
 *   должны быть проверены EcoSplineCheck. Сложность O(n), память O(n).
 *   coefs - 4*(n-1) элементов, work - 2*n элементов (рабочий буфер).
 * </description>
 *
 */
static int16_t ECOSPL_FN(EcoSplineSolve)(/* in */ const ECOSPL_REAL* x, /* in */ const ECOSPL_REAL* y, /* in */ uint32_t n, /* in */ const ECO_SPLINE_ENDS_T* pEnds,
                                         /* out */ ECOSPL_REAL* coefs, /* in, out */ ECOSPL_REAL* work) {
    ECOSPL_REAL* cp = work;       /* c' прогонки */
    ECOSPL_REAL* s = work + n;    /* правая часть d', затем решение (наклоны) */
    ECOSPL_REAL a, b, c, r, den, h, d, c0, c1;
    uint32_t lt = ECO_SPLINE_END_NOT_A_KNOT;
    uint32_t rt = ECO_SPLINE_END_NOT_A_KNOT;
    ECOSPL_REAL lv = 0;
    ECOSPL_REAL rv = 0;
    uint32_t i = 0;
    int16_t result = ERR_ECO_SUCCESS;

    if (pEnds != 0) {
        lt = pEnds->leftType;
        rt = pEnds->rightType;
        lv = (ECOSPL_REAL)pEnds->leftValue;
        rv = (ECOSPL_REAL)pEnds->rightValue;
    }

    if (n == 2) {
        /* not-a-knot на отрезке из двух узлов - наклон хорды (как scipy CubicSpline) */
        d = (y[1] - y[0]) / (x[1] - x[0]);
        if (!ECOSPL_ISFINITE(d)) {
            return ERR_ECOADVANCEDMATH_NOT_FINITE;
        }
        if (lt == ECO_SPLINE_END_NOT_A_KNOT) {
            lt = ECO_SPLINE_END_FIRST_DERIVATIVE;
            lv = d;
        }
        if (rt == ECO_SPLINE_END_NOT_A_KNOT) {
            rt = ECO_SPLINE_END_FIRST_DERIVATIVE;
            rv = d;
        }
    }

    if (n == 3 && lt == ECO_SPLINE_END_NOT_A_KNOT && rt == ECO_SPLINE_END_NOT_A_KNOT) {
        /* Парабола через три точки (как MATLAB): p' = d0 + k*(2x - x0 - x1) */
        h = x[1] - x[0];
        c0 = (y[1] - y[0]) / h;
        c1 = (y[2] - y[1]) / (x[2] - x[1]);
        d = (c1 - c0) / (x[2] - x[0]);
        if (!ECOSPL_ISFINITE(d) || !ECOSPL_ISFINITE(c0)) {
            return ERR_ECOADVANCEDMATH_NOT_FINITE;
        }
        s[0] = c0 - d * h;
        s[1] = c0 + d * h;
        s[2] = c0 + d * ((x[2] - x[0]) + (x[2] - x[1]));
    }
    else {
        /* Прямой ход прогонки */
        for (i = 0; i < n; i++) {
            if (i == 0) {
                result = ECOSPL_FN(EcoSplineRow)(x, y, n, i, lt, lv, &a, &b, &c, &r);
            }
            else if (i == n - 1) {
                result = ECOSPL_FN(EcoSplineRow)(x, y, n, i, rt, rv, &a, &b, &c, &r);
            }
            else {
                result = ECOSPL_FN(EcoSplineRow)(x, y, n, i, 0, 0, &a, &b, &c, &r);
            }
            if (result != ERR_ECO_SUCCESS) {
                return result;
            }
            if (i == 0) {
                den = b;
            }
            else {
                den = b - a * cp[i - 1];
            }
            if (den == 0 || !ECOSPL_ISFINITE(den)) {
                return ERR_ECOADVANCEDMATH_SINGULAR;
            }
            cp[i] = c / den;
            s[i] = (i == 0) ? r / den : (r - a * s[i - 1]) / den;
        }
        /* Обратный ход */
        for (i = n - 1; i > 0; i--) {
            s[i - 1] = s[i - 1] - cp[i - 1] * s[i];
        }
    }

    /* Коэффициенты кусков: d = y, c = s, b = (3*delta - 2*s0 - s1)/h, a = (s0 + s1 - 2*delta)/h^2 */
    for (i = 0; i + 1 < n; i++) {
        h = x[i + 1] - x[i];
        d = (y[i + 1] - y[i]) / h;
        c0 = s[i];
        c1 = s[i + 1];
        coefs[4 * i + 0] = ((c0 + c1 - 2 * d) / h) / h;
        coefs[4 * i + 1] = (3 * d - 2 * c0 - c1) / h;
        coefs[4 * i + 2] = c0;
        coefs[4 * i + 3] = y[i];
        if (!ECOSPL_ISFINITE(coefs[4 * i]) || !ECOSPL_ISFINITE(coefs[4 * i + 1]) || !ECOSPL_ISFINITE(c0)) {
            return ERR_ECOADVANCEDMATH_NOT_FINITE;
        }
    }
    return ERR_ECO_SUCCESS;
}
```
